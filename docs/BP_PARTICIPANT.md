# ИИ-агент как участник бизнес-процессов

Агента можно сделать участником любого бизнес-процесса, как обычного сотрудника. Автор процесса в дизайнере назначает шаг пользователю «ИИ-агент» и пишет в задании, что сделать. Агент сам находит свои задания, изучает документ (карточку, письма, файлы, задачи, историю) и выполняет задание: утверждает или отклоняет, отмечает ознакомление или заполняет поля.

Приложение не нужно, входящий доступ к агенту тоже: агент работает через вебхук и опрашивает свои задания (`bizproc.task.list`).

## Включение

```env
BP_AGENT=true
BP_POLL_INTERVAL=60                       # как часто проверять задания, сек
BP_AGENT_DECISIONS=approve,reject,ok,cancel  # какие решения агенту можно принимать самому
BP_MIN_CONFIDENCE=0.5                     # ниже этой уверенности решение передаётся человеку
BP_AGENT_ESCALATE_TO=15                   # ID сотрудника, которому передавать сложные случаи
BP_TIMELINE_NOTE=true                     # отметка в таймлайне объекта CRM о принятом решении
# BP_AGENT_PROMPT_FILE=bp_rules.md        # общие правила компании для всех заданий БП
```

После изменения настроек перезапустите `b24agent serve`. Пользователь «ИИ-агент» — это владелец вебхука, то есть сервисная учётка.

## Как поставить агенту задание в дизайнере

| Действие в дизайнере | Что делает агент | Решения |
|---|---|---|
| **Утверждение документа** | изучает документ и утверждает или отклоняет его с обоснованием | `approve` / `reject` |
| **Ознакомление с документом** | изучает документ и отмечает ознакомление с кратким выводом в комментарии | `ok` |
| **Запрос дополнительной информации** | изучает документ и **заполняет поля** задания: оценку, резюме, риск, сумму, ответственного | `ok` + поля |
| **Запрос доп. информации с отклонением** | заполняет поля или отказывается | `ok` / `cancel` |

1. Добавьте действие и в поле «Ответственные» укажите пользователя **«ИИ-агент»**.
2. В **описании задания** напишите инструкцию для агента: это его задача. Можно подставлять поля документа (`{=Document:...}`), и агент увидит их уже со значениями.
3. Для «Запроса доп. информации» заведите поля, которые агент должен заполнить. Поддерживаются типы: строка, текст, число, дробное, да/нет, список (агент выбирает вариант), дата, пользователь. Файлы агент не загружает.
4. Дальше процесс идёт по результату как обычно: агент утвердил — ветка «Да», отклонил — ветка «Нет», заполнил поля — значения доступны в следующих шагах (`{=A123:risk}`).

### Примеры описаний заданий

**Проверка договора перед юристом (утверждение):**
> Проверь договор во вложениях сделки. Утверди, если: оплата не позже 30 дней, неустойка не выше 0,1 % в день, есть пункт о конфиденциальности. Если какого-то условия нет или договор не найден — отклони и перечисли, что не так. Сумма в договоре должна совпадать с суммой сделки {=Document:OPPORTUNITY}.

**Оценка входящей заявки (запрос информации, поля «Риск», «Резюме», «Срочно»):**
> Прочитай последнее входящее письмо клиента и вложения. Заполни: Риск — по бюджету и срокам, Резюме — что просит клиент, в 2–3 предложениях, Срочно — да, если клиент просит ответ быстрее 2 дней.

**Ознакомление со сводкой (ознакомление):**
> Ознакомься с проектом и в комментарии кратко опиши его состояние: стадия, просроченные задачи, последние договорённости из переписки.

## Безопасность и контроль

- Агент **ничего не меняет в CRM**: при изучении документа у него только читающие инструменты. Задание выполняет код агента по проверенному ответу модели, а не сама модель.
- **Проверка ответа.** Решение должно подходить к типу задания, обязательные поля должны быть заполнены, значения списков — существовать. Если ответ не прошёл проверку, агент делает одну повторную попытку, а затем передаёт задание человеку.
- **Передача человеку (эскалация)** происходит, если:
  - модель сама ответила `escalate` (не хватает данных, неясная инструкция);
  - решение не входит в `BP_AGENT_DECISIONS`;
  - уверенность ниже `BP_MIN_CONFIDENCE`;
  - тип задания не поддерживается.

  Тогда агент пишет `BP_AGENT_ESCALATE_TO` в личку причину и своё мнение и пытается делегировать ему задание (`bizproc.task.delegate`). Если делегировать не получилось, задание остаётся у пользователя «ИИ-агент»: администратор может делегировать его вручную.
- **Комментарий к решению** всегда начинается с «ИИ-агент: …», его видно в истории процесса.
- **Без повторов.** Каждое задание обрабатывается один раз (до 3 попыток при сбоях), за один проход — не больше `BP_MAX_PER_CYCLE` заданий.
- **Осторожный старт.** Для первых процессов поставьте `BP_AGENT_DECISIONS=ok`: агент будет заполнять поля и отмечать ознакомление, а утверждения и отказы передаст человеку вместе со своим мнением.

## Ограничения

- Создавать и менять **шаблоны** процессов агент не может: `bizproc.workflow.template.add/update` работают только в контексте приложения с правами администратора. Роботы на стадиях через REST не настраиваются вовсе.
- Документы **универсальных списков**: агент видит название, ссылку и поля задания. Карточку элемента он читает, только если инструкция указывает ID списка.
- **Время реакции** — до `BP_POLL_INTERVAL` секунд плюс время работы модели.
