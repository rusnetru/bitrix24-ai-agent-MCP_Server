# MCP Server для коробочного Битрикс24

## Аннотация

`b24agent mcp` — MCP-сервер ([Model Context Protocol](https://modelcontextprotocol.io/)). Он даёт любому ИИ-клиенту доступ к **коробочному Битрикс24** через входящий вебхук. Подходят Claude Desktop, Claude Code, Cursor, VS Code и внутренние агентные платформы. Сервер публикует **42 инструмента** для работы с:

- CRM и смарт-процессами;
- перепиской и файлами на Диске;
- задачами;
- сотрудниками и оргструктурой;
- календарём;
- бизнес-процессами;
- универсальными списками.

Есть также универсальный вызов любого метода REST с политикой безопасности. Это тот же набор инструментов, которым пользуется встроенный чат-бот «ИИ-агент». Права ограничены правами пользователя вебхука, а режим только чтения и плагины компании действуют одинаково для обоих.

---

## Запуск и подключение

Сервер работает по **stdio**: клиент сам запускает процесс и общается с ним через стандартный ввод и вывод. Сетевой порт не открывается. Настройки читаются из `.env` в каталоге проекта (или передаются через `--env`). Для MCP нужны только `BITRIX_WEBHOOK_URL` и при необходимости `BITRIX_VERIFY_SSL`. LLM для MCP-сервера не нужна: модель — на стороне клиента.

```bash
uv run b24agent mcp                    # из каталога проекта
uv run b24agent --env /etc/b24agent.env mcp
```

**Claude Desktop / Cursor / VS Code** (`claude_desktop_config.json`, `.cursor/mcp.json` и т.п.):

```json
{
  "mcpServers": {
    "bitrix24": {
      "command": "uv",
      "args": ["--directory", "/path/to/bitrix24-ai-agent-MCP_Server", "run", "b24agent", "mcp"]
    }
  }
}
```

**Claude Code:**

```bash
claude mcp add bitrix24 -- uv --directory /path/to/bitrix24-ai-agent-MCP_Server run b24agent mcp
```

Без uv: `pip install -e .`, затем команда `b24agent mcp` (или `python -m b24agent mcp`).

Проверить, какие инструменты увидит клиент, можно командой `uv run b24agent tools`. Инструменты с пометкой `bot` в MCP не публикуются, а при `AGENT_ALLOW_WRITE=false` скрываются и помеченные `W`.

## Как устроено

| Что | Как |
|---|---|
| Имя сервера | `bitrix24-box` |
| Транспорт | stdio (MCP SDK `mcp>=1.4`, low-level `Server`) |
| Возможности | только **tools**; resources и prompts не публикуются |
| Ответ инструмента | один `TextContent` с компактным JSON: пустые поля убраны, у объектов есть `url` на карточку в портале |
| Ошибки | возвращаются в ответе как `{"error": "...", "details": "..."}`: коды Битрикс24, «нет прав», «нет такого метода», «запись отключена». Сервер при этом не падает |
| Длинные ответы | обрезаются до 15 000 символов с подсказкой сузить фильтр; файлы читаются частями (`offset`) |
| Пользователь | все вызовы идут от **пользователя вебхука**. «Текущего собеседника» в MCP нет, поэтому для «моих задач» и подобного передавайте ID сотрудника явно (`RESPONSIBLE_ID`, `responsible_id`, `owner_id`) |
| Повторы | ретраи при `QUERY_LIMIT_EXCEEDED`, `OPERATION_TIME_LIMIT` и сетевых сбоях |

### Как указывать объекты

Параметр `entity` принимает тип объекта в любом удобном виде:
- английское или русское название: `deal`, `contact`, `company`, `lead`, `quote`, `invoice`, «сделка», «контакт»;
- **entityTypeId** смарт-процесса (`1038`);
- код (`DYNAMIC_1038`);
- **название смарт-процесса** («Проекты»).

Список типов портала возвращает `crm_entity_types`.

## Инструменты

Обозначения: `*` — обязательный параметр, **W** — изменяет данные (скрывается при `AGENT_ALLOW_WRITE=false`).

### Справочники CRM

| Инструмент | Параметры | Что делает |
|---|---|---|
| `crm_entity_types` | — | типы CRM-объектов: стандартные и смарт-процессы с `entityTypeId` |
| `crm_fields` | `entity*`, `only_custom` | поля типа: код, название, тип, обязательность, варианты списков (в том числе пользовательские `ufCrm...`) |
| `crm_pipelines` | `entity*` | воронки (направления) и их стадии с кодами `stageId` и семантикой |

### CRM и смарт-процессы

| Инструмент | Параметры | Что делает |
|---|---|---|
| `crm_list` | `entity*`, `filter`, `select`, `order`, `limit` | список элементов (`crm.item.list`). Фильтр задаётся в camelCase с операторами: `{"stageId":"C2:NEW","%title":"ромашка",">opportunity":1000,"assignedById":5}` |
| `crm_search` | `entity*`, `query*`, `limit` | быстрый поиск по названию, ФИО, телефону или email (для контактов, компаний и лидов есть поиск дублей по телефону и email) |
| `crm_get` | `entity*`, `id*` | полная карточка: поля подписаны человеческими названиями, значения списков раскрыты, стадия названа словами; телефоны и email; ответственные по именам |
| `crm_related` | `entity*`, `id*` | связанные объекты: контакты, компания, задачи |
| `crm_timeline` | `entity*`, `id*`, `limit` | история: комментарии таймлайна и дела (звонки, письма, встречи) |
| `crm_stage_history` | `entity*`, `id*` | движение по стадиям с датами |
| `crm_add` **W** | `entity*`, `fields*`, `phone`, `email` | создать элемент |
| `crm_update` **W** | `entity*`, `id*`, `fields*`, `phone`, `email` | изменить поля, в том числе стадию (`{"stageId": ...}`) |
| `crm_comment_add` **W** | `entity*`, `id*`, `text*` | комментарий в таймлайн (автор — пользователь вебхука) |
| `crm_todo_add` **W** | `entity*`, `id*`, `deadline*`, `title`, `description`, `responsible_id` | создать дело (todo) |

### Переписка и документы

| Инструмент | Параметры | Что делает |
|---|---|---|
| `crm_emails` | `entity*`, `id*`, `limit` | письма в таймлайне: тема, входящее или исходящее, дата, адресаты, начало текста, число вложений |
| `crm_email_read` | `id*`, `max_chars` | полный текст письма и его вложения со ссылками `ref` |
| `crm_files` | `entity*`, `id*` | все файлы объекта: поля «Файл» и «Файл (Диск)», вложения комментариев, писем и дел. Каждый файл возвращается с `ref` |
| `file_read` | `ref` или `disk_file_id`, `offset`, `max_chars` | скачать файл и вернуть текст. Поддерживаются PDF, DOCX, XLSX, PPTX, ODT, RTF, TXT, CSV, HTML, EML. Длинный файл читается частями: передайте `next_offset` в `offset`. Текст кэшируется |

### Задачи

| Инструмент | Параметры | Что делает |
|---|---|---|
| `task_list` | `filter`, `entity` + `id`, `order`, `limit` | задачи. Фильтр задаётся в верхнем регистре: `{"RESPONSIBLE_ID":5,"REAL_STATUS":[2,3],"<DEADLINE":"2026-12-01"}`. Чтобы получить задачи объекта CRM, передайте `entity` + `id` |
| `task_get` | `id*` | описание, участники, чек-лист, привязки к CRM |
| `task_comments` | `id*`, `limit` | комментарии задачи |
| `task_add` **W** | `title*`, `responsible_id`, `deadline`, `description`, `priority`, `auditors`, `group_id`, `entity` + `crm_id` | создать задачу, в том числе с привязкой к сделке или смарт-процессу |
| `task_update` **W** | `id*`, `fields`, `action` | изменить поля; `action`: `start`, `complete`, `defer`, `renew` |
| `task_comment_add` **W** | `id*`, `text*` | комментарий к задаче |

### Сотрудники, оргструктура, календарь

| Инструмент | Параметры | Что делает |
|---|---|---|
| `user_search` | `query*`, `limit` | найти сотрудников по ФИО, email или должности и узнать их ID |
| `user_get` | `id` | карточка сотрудника (в MCP `id` обязателен по смыслу) |
| `department_list` | `id`, `parent_id`, `name`, `with_users`, `limit` | подразделения; с `with_users` вместе с `id` — состав подразделения |
| `workgroup_list` | `query`, `filter`, `limit` | рабочие группы и проекты |
| `calendar_events` | `type`, `owner_id`, `from`, `to`, `limit` | события календаря пользователя, группы или компании |
| `calendar_accessibility` | `user_ids*`, `from*`, `to*` | занятость сотрудников, чтобы подобрать время встречи |
| `calendar_event_add` **W** | `name*`, `from*`, `to*`, `owner_id`, `attendees`, `description`, `location`, `section_id` | создать событие или встречу |

### Бизнес-процессы и универсальные списки

| Инструмент | Параметры | Что делает |
|---|---|---|
| `bp_tasks` | `user_id`, `limit` | открытые задания БП (согласования, ознакомления, запросы) с описанием и полями ввода |
| `bp_task_complete` **W** | `task_id*`, `decision*`, `comment`, `fields` | выполнить задание пользователя вебхука: `approve`, `reject`, `ok` или `cancel` |
| `bp_templates` | `entity` | шаблоны бизнес-процессов (нужны права администратора) |
| `bp_start` **W** | `template_id*`, `entity*`, `id*`, `parameters` | запустить процесс для элемента CRM или смарт-процесса (нужны права администратора) |
| `lists_get` | `iblock_type`, `group_id` | универсальные списки портала или группы |
| `list_fields` | `list_id*`, `iblock_type` | поля списка (`PROPERTY_xxx`, типы, варианты) |
| `list_elements` | `list_id*`, `filter`, `element_id`, `iblock_type`, `limit` | элементы списка |
| `list_element_add` **W** | `list_id*`, `fields*`, `element_code`, `iblock_type` | добавить элемент |

### Универсальный доступ к REST

| Инструмент | Параметры | Что делает |
|---|---|---|
| `bitrix_call` | `method*`, `params`, `api_version` (`2` или `3`) | вызвать любой метод REST портала, включая REST 3.0 (`/rest/api/`). Подчиняется политике `BITRIX_CALL`, см. ниже |
| `bitrix_method_info` | `method` или `methods` | есть ли метод на этой коробке и доступен ли он по правам вебхука (`method.get`), а также разрешает ли его политика |

### Только в чате с ботом (в MCP не публикуются)

`chat_bind_entity`, `chat_create_for_entity`, `timeline_watch`. Им нужен контекст разговора в мессенджере.

## Примеры запросов к ИИ-клиенту

- «Найди в смарт-процессе „Проекты“ все элементы на стадии „Согласование“ с бюджетом больше 1 млн и покажи ответственных»: `crm_entity_types` → `crm_pipelines` → `crm_list` → `user_get`.
- «Что клиент пишет по сделке 123? Прочитай вложения и составь ответ»: `crm_emails` → `crm_email_read` → `file_read`.
- «Собери по проекту 15 сводку: стадия, просроченные задачи, последние договорённости»: `crm_get`, `task_list` (`entity` + `id`), `crm_timeline`.
- «Когда в четверг свободны Петров и Сидорова? Создай встречу на час»: `user_search` → `calendar_accessibility` → `calendar_event_add`.
- «Какие универсальные списки есть и что в списке „Командировки“ за ноябрь?»: `lists_get` → `list_fields` → `list_elements`.
- «Есть ли на портале REST 3.0 для задач?»: `bitrix_method_info`.

## Настройки, которые влияют на MCP

| Переменная | Влияние |
|---|---|
| `BITRIX_WEBHOOK_URL`, `BITRIX_VERIFY_SSL`, `BITRIX_TIMEOUT` | подключение к порталу |
| `AGENT_ALLOW_WRITE=false` | режим только чтения: инструменты **W** не публикуются |
| `TOOLS_DISABLED=bp_start,crm_add` | скрыть отдельные инструменты |
| `BITRIX_CALL=off\|read\|full`, `BITRIX_CALL_ALLOW`, `BITRIX_CALL_DENY` | политика `bitrix_call` |
| `TOOL_PLUGINS`, `PLUGINS_DIR` | плагины компании: их инструменты появляются в MCP автоматически |
| `FILES_MAX_MB`, `FILE_READ_CHARS` | лимиты чтения файлов |
| `DATA_DIR` | где лежит кэш текста файлов (SQLite) |

## Безопасность

- **Права = права пользователя вебхука.** Для MCP разумно создать **отдельный вебхук** от учётки с минимально нужными правами, а для аналитиков включить `AGENT_ALLOW_WRITE=false`.
- **`bitrix_call`.** По умолчанию (`read`) разрешены только читающие методы: `*.get`, `*.list`, `*.fields` и подобные. В режиме `full` запись разрешена, но закрыты опасные методы:
  - удаление (`*.delete`, `*.deletetree`), `event.*`, `placement.*`;
  - `imbot.*`, `user.add/update`, `*.userfield.*`, `crm.type.*`;
  - шаблоны и роботы БП и другие.

  Открыть конкретный метод можно через `BITRIX_CALL_ALLOW`. `batch` через `bitrix_call` запрещён.
- **Секреты.** URL вебхука хранится только в `.env` и не попадает в ответы инструментов.
- **Данные.** Сервер отдаёт данные портала той модели, к которой подключён клиент. Если клиент работает с внешней моделью, данные CRM уйдут ей. В закрытом контуре подключайте клиенты, которые используют внутреннюю LLM.

## Расширение

Свой инструмент добавляется плагином: Python-файл в `plugins/` с функцией `register(tb)`. После перезапуска он появляется и в MCP, и у чат-бота. Подробности — в [EXTENDING.md](EXTENDING.md), справочник методов коробки — в [BITRIX_BOX_API.md](BITRIX_BOX_API.md).

## Ограничения и планы

- Транспорт только **stdio**. Сетевой MCP (Streamable HTTP) для подключения внутренних платформ по сети запланирован (`mcp.server.streamable_http`).
- Публикуются только tools. MCP resources (например, `deal://123`) и prompts пока не реализованы.
- Контекста «текущего пользователя» нет: все вызовы идут от пользователя вебхука.
- Вживую на коробке сервер ещё не проверялся. Тесты проходят на заглушках портала.
